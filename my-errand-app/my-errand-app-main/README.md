# My Errand

Marketplace-style platform for booking, managing, and paying for errands.  
Roles: **clients**, **runners/agents**, and **admins**.

- Create and manage errands  
- Escrow-style wallet (spendable → escrow → withdrawable)  
- Paystack / PayPal deposits (optional keys)  
- JWT auth, Socket.IO, i18n  

## Quick start (local or GitHub Codespaces)

```bash
npm run bootstrap   # creates .env, installs deps, starts MariaDB, loads schema
npm run dev         # API on :5000 + React on :3001
```

Or step by step:

```bash
npm run setup:env
npm install
npm run install-client
npm run db:start
npm run dev
```

- API health: http://localhost:5000/health  
- App: http://localhost:3001  

**Codespaces:** open the repo in a Codespace (`.devcontainer` runs setup). Forward ports **5000** and **3001**. See [CODESPACES.md](./CODESPACES.md).

## Requirements

- Node.js 18+  
- Docker (for MariaDB) — or your own MySQL matching `.env`  
- Optional: Paystack / PayPal keys for live payments  

## Configuration

Copy is automatic via `npm run setup:env`. Important variables in `.env`:

| Variable | Purpose |
|----------|---------|
| `USE_MONGO` | Keep `false` — wallet & errands use **MySQL only** |
| `JWT_SECRET` | Auto-generated by setup; required in production |
| `MYSQL_*` | Database connection (matches Docker defaults) |
| `ALLOW_CODESPACES` | `true` → CORS allows `*.github.dev` |
| `PAYSTACK_*` / `PAYPAL_*` | Optional payment providers |

## Architecture

| Path | Role |
|------|------|
| `server.js` | HTTP + Socket.IO entry |
| `app.js` | Express app, CORS, routes |
| `routes/` | auth, errands, wallet, payments, admin, clients, agents |
| `utils/` | wallet helpers, currencies, payment config |
| `database/` | SQL schemas (loaded by Docker on first start) |
| `client/` | React (Webpack) frontend |
| `scripts/` | setup-env, bootstrap, DB setup |

## Scripts

| Command | What it does |
|---------|----------------|
| `npm run bootstrap` | Full auto setup |
| `npm run setup` | Env + install root + client |
| `npm run setup:env` | Create/update `.env` only |
| `npm run db:start` | Start MariaDB container |
| `npm run db:stop` | Stop MariaDB |
| `npm run setup-db` | Apply SQL schemas |
| `npm run dev` | API + client together |
| `npm run server` | API only |
| `npm run build` | Production client build |

## Demo login

From the Login page use **Demo login**, or:

`POST /api/auth/demo-login` → creates/uses `demo@example.com` (dev only).

## Production notes

- Set `NODE_ENV=production` and a strong `JWT_SECRET` (app refuses to start without it in production).  
- Set real `FRONTEND_URL` / `CLIENT_URL`.  
- Do not commit `.env`.  
- Payments stay simulated until provider keys are set.

## Production readiness notes

- Set `NODE_ENV=production`, strong `JWT_SECRET`, and `ALLOW_DEMO_LOGIN=false`.
- Primary DB is MySQL (`USE_MONGO=false`). Docker loads full schema + wallet + gift cards + alignment.
- Auth is unified at `/api/auth`. Legacy `/api/clients` and `/api/agents` return 410 Gone.
- Role guards: clients create/pay; runners accept/complete; admin routes require `user_type=admin`.
- Paystack webhook is public; all other `/api/wallet/*` require JWT.
- Seed: `npm run seed` (optional `SEED_ADMIN=true` for admin@example.com).

## Auth extras

- `POST /api/auth/forgot-password` / `POST /api/auth/reset-password`
- `POST /api/auth/verify-email` (authenticated)
- Login rate limit: 20 attempts / 15 minutes
- Admin UI: `/admin` (requires `user_type=admin`)
